In brief

This project is a kit for running Pika H3 Flex on your own computer. Flex is an open model from Pika that turns text into video with synchronized sound in just 6 steps. It isn’t a full model: it consists of two adapters (LoRAs, a “tuning” of about 2 GB) that plug into MiniMax H3. It’s for people with a powerful GPU, such as the NVIDIA DGX Spark, who want to generate video without paying per clip. To use it, you need ComfyUI with the H3 models; the kit includes the commands, generator, and memory protection.

What it is

Video and sound in the same pass, at home

Pika released the Flex weights on 10/29/2026. We downloaded, configured, and tested them on a DGX Spark (GB10, 128 GB of unified memory).

⚡ 6 steps, not 50

Pika trained Flex to generate in 6 denoising steps. In practice, generation itself takes about 30 s for a short clip.

🔊 Video with sound

The same pass generates both image and audio: wind, footsteps, splash, music. Describe the scene and sound in the prompt.

🏠 Local and open

Runs in ComfyUI on your machine. No credits per clip, no cloud queue. The open version goes up to 768p.

How it works

From text to MP4

gera.py sends ComfyUI the same graph as the official Flex template, using the names of the models you have.

Prompt (scene + sound)→ Qwen3-VL reads the text→ MiniMax H3 + LoRA Flex→ 6 sigmas + lcm→ Video and audio VAE→ MP4 with sound

Manual sigmas

1.0, 0.972973, 0.923077, 0.8, 0.571429, 0.333333, 0.0. Selecting “6 steps” in any sampler won’t reproduce Flex.

lcm sampler

Fresh noise at every step, with no CFG. LoRA strength 1.0, as specified by Pika.

17k + 5 frames

H3 requires 73 frames (3 s) or 124 (5 s) at 24 fps. --segundos does the math.

Prerequisites

What needs to be ready

If MiniMax H3 already runs on your machine, all you need to do is download the two Flex LoRAs.

GPU with ~60 GB free

Tested on the DGX Spark (GB10, 128 GB unified memory). On a smaller card, use smaller quantized versions.

# check free memory
free -g

Recent ComfyUI

With the native H3 nodes: MiniMaxH3ImageToVideo, ManualSigmas, SamplerCustomAdvanced. Tested on 0.33.0.

# in the ComfyUI folder
git pull

MiniMax H3 models

In models/: minimax_h3_fl2va_pruned_fp8_scaled (21 GB), qwen3vl_32b_minimax_h3_int8_convrot (27 GB), video and audio VAEs (5.8 GB).

# list what you have
ls models/diffusion_models models/text_encoders models/vae
User guide · step by step

From zero to your first clip

These are the commands that worked here. Replace the paths with yours.

1

Download the kit

Scripts, workflows, and examples.

git clone https://github.com/inematds/pika-h3-flex && cd pika-h3-flex
2

Download the Flex LoRAs (ComfyUI format)

Two files of about 2 GB each. The hash verifies that they downloaded completely.

hf download Pika-Labs/Pika-H3-Flex --include 'comfy/*' --local-dir pika-flex
cd pika-flex/comfy && sha256sum -c SHA256SUMS   # both: OK
mv loras/pika_h3_flex_*_comfy_bf16.safetensors /path/to/ComfyUI/models/loras/
3

Start ComfyUI with the memory options

The script already passes the three options that prevent duplicate weights. Adjust COMFY_DIR and VENV.

COMFY_DIR=~/ComfyUI VENV=~/ComfyUI/venv ./scripts/comfyui-start.sh
# starts on port 8299 with --disable-dynamic-vram --disable-pinned-memory --cache-none
4

Turn on the memory guard

It checks the machine’s free memory every 3 s and stops ComfyUI before the system freezes.

./scripts/guarda.sh guarda.log 8 &   # 8 = limit in GB
5

Generate

Use one prompt or a file with several prompts (one per block). The models load only once.

python3 scripts/gera.py --prompt "integrated_multimodal_description: [Shot 1] ... overall_soundscape: ..."
python3 scripts/gera.py --arquivo exemplos/prompts.txt --largura 1344 --altura 768 --segundos 5
# output: ComfyUI/output/pika_flex/clip01_00001_.mp4 ...
6

Shut down

ComfyUI runs inside a systemd scope.

systemctl --user stop comfyui-h3.scope
+

Prefer ComfyUI’s interface?

Open the workflows in workflows/ (t2v, fl2va, ref2va): they are the official Flex templates with the names changed to match the models in the table above.

workflows/pika_flex_t2v_ui.json   # drag it into the ComfyUI interface
The memory trap

Unified memory can be misleading

On the DGX Spark, the GPU and CPU share the same memory. That changed everything in the test.

💥 First test: 0 GB free

The systemd limit was set to 41 GB, and the machine still ran out of memory. The system killed ComfyUI. The limit doesn’t account for the GPU’s share.

🔍 The cause

ComfyUI kept the weights twice, once in RAM and once in the GPU. Loading alone used more than 80 GB.

✅ The fix

--disable-dynamic-vram --disable-pinned-memory --cache-none plus guarda.sh. This left plenty of memory, even with another image service running.

⚠️ Run it alone on the GPU

In a batch of 1344×768 clips running alongside other video renders, the GPU ran out of memory and the server froze. guarda.sh checks the machine’s free memory, but it can’t prevent the GPU driver from running out of memory. Before generating, close other GPU intensive workloads and start with the smaller size (832×480).
